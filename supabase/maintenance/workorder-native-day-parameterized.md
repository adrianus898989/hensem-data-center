The parent missing-receipt branch and the full-range unique helper now keep their existing NEWAR fiat-workorder predicates inside a correlated `LATERAL` subquery with `OFFSET 0`. This keeps platform and native-local date bounds in the existing partial index scan, instead of applying dates after a broad merge join. All original fields, nullable amounts, explicit original-order references, global range deduplication, provider rules, coverage and permissions remain unchanged. The excluded-USDT diagnostic branch is unchanged.

Apply `workorder-native-day-parameterized.sql`; undo with `workorder-native-day-parameterized.rollback.sql`. Both scripts atomically check the complete expected function versions/metadata, replace exactly two joins, preserve other routines and source metadata, and compare financial dependency values before and after. Their eight-second timeout is only for the maintenance transaction. Existing RPC budgets, indexes, grants, source writers, schedulers and cache semantics do not change. No new database object is created.

Actual candidate evidence showed platform and date conditions inside the index. This was not a full-page acceptance test and cannot establish a full weekly speedup; the earlier two-day timeout is a different scope.
